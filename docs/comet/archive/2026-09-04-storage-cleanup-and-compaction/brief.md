# 目标
优化 ClipOne 存储清理机制：点击清空时彻底清空存储文件，日常手动删除及超出最大记录数限制的历史数据具备物理清理与日志压缩（Compaction）机制，避免文件无节制膨胀。

# 范围
- `service/StorageService.cs` 存储服务逻辑改造。
- 清空逻辑改造：清空时直接物理清空存储文件内容与内存。
- 日常单项删除与超量数据物理清理：引入 Compaction 机制，清理墓碑与超量废弃数据。

# 非目标
- 不改动网络通信、Web 渲染或剪贴板监听格式支持。
- 不引入重型数据库引擎（保持轻量 JSONL / 文本格式）。

# 验收示例
- Scenario: 点击清空后文件内容彻底清空
  - WHEN 用户在托盘或界面触发清空操作
  - THEN 界面历史即时清空，且 events.jsonl 文件内容被直接物理清空为 0 字节，重新加载后不再恢复旧数据。
- Scenario: 手动删除与超量数据自动压缩
  - WHEN 用户手动删除条目或复制新条目导致记录数超过最大限制（如 300 条）
  - THEN 触发文件压缩（Compaction），events.jsonl 文件中被删除及溢出范围的历史数据被彻底丢弃，文件体积收敛。

# 约束与不变量
- 保持现有 Native AOT 与零反射 Source Generator 兼容性。
- 保证文件写操作的线程安全与原子性，避免并发读写损坏。

# 决策
- 清空操作范围：清空时彻底清空本地 data/devices 目录下所有设备的 events.jsonl 文件，防止重启后其他设备的历史数据再次回显，同时内存清空。
- Compaction 压缩策略：采用“阈值触发 + 启动/退出时自动压缩”策略。平时新增快速单行追加；当废弃行（墓碑/超量行）累积达到阈值（如 >= 30 条），或程序启动/退出时，自动执行 Compaction 重写瘦身，只保留当前设备在最新 <= 300 条有效记录，原子替换写入 events.jsonl。

- 编译运行正常，零警告零报错。
